# 法学期刊论文 Skill README 专业化设计

## 目标

把 README 从功能清单改造成专业、可信、易浏览的 GitHub 项目首页。视觉上采用“法学期刊的克制感 + 现代开源项目的信息清晰度”，并与书稿 Skill 保持同一家族风格。README 同时提供可直接照做的使用指南，并使用项目专属 Banner 和正文插图建立视觉识别。

## 设计原则

- 使用纯 Markdown、GitHub 支持的少量 HTML 和仓库内自有图片；除状态徽章可使用 Shields.io 外，不依赖第三方图片服务。
- 以深蓝为主强调色，表达研究、证据和可靠性。
- 徽章只表达可由仓库内容支持的事实，不暗示 Hermes、OpenAI 或 Obsidian 官方认证。
- 保留现有安装、边界、示例、Obsidian 工作流和文件结构等有效内容，但压缩重复表达。
- 桌面端和移动端都应保持可读；不依赖只能在浅色模式下辨认的颜色。

## 首屏

首屏居中展示：

1. 项目专属宽幅 Banner；
2. 中文项目名；
3. 英文副标题 `Chinese Legal Journal Writing Skill`；
4. 一句价值主张：强调证据可追溯、引注完整和目标期刊适配；
5. Hermes、Codex、Obsidian、Citation Integrity、MIT License 五枚静态徽章；
6. 项目内快捷导航。

MIT License 徽章直接链接 `LICENSE`。其他徽章不得链接到不存在或与项目无关的页面。

## 信息架构

README 按以下顺序组织：

1. 首屏与快捷导航；
2. “为什么使用”三栏价值表；
3. 核心能力；
4. 六阶段论文工作流；
5. 引用与真实性硬边界；
6. 快速安装；
7. 完整使用指南；
8. Obsidian 协作方式；
9. 证据链正文插图；
10. 仓库结构；
11. 适用与不适用范围；
12. 来源说明。

## 使用指南

使用指南必须让第一次接触 Skill 的用户可以独立完成一次任务，包含：

1. **准备材料**：研究问题、允许读取的资料范围、法律与事实资料截止日期、目标期刊和交付格式；
2. **选择模式**：解释 `PLAN / RESEARCH / OUTLINE / DRAFT / REVISE / AUDIT / ADAPT` 的适用场景；
3. **调用 Skill**：分别提供 Hermes 与 Codex 的可复制调用示例；
4. **使用项目卡与来源登记**：说明何时使用项目卡、来源登记和论点—证据—引注表；
5. **生成工作稿**：展示包含 `[^S001]` 和 `[^待核引注-01]` 的最小示例；
6. **完成终检**：解释工作稿与最终稿的区别，并链接引注审核和投稿检查模板；
7. **常用任务模板**：以折叠区提供选题诊断、提纲、分节起草、引用审核和期刊适配提示词。

使用指南不得承诺自动访问用户的 Obsidian Vault、自动核验所有法律资料或保证期刊录用。

通过图片生成工具创建两个仓库内 PNG 资产：

| 文件 | 用途 | 构图与风格 |
|---|---|---|

共同约束：

- 与书稿图片保持同一视觉语言，但论文图片更轻、更精密；
- 不使用国徽、法院徽记、旗帜、真实人物、品牌 Logo、天平或法槌堆砌；
- 不出现伪造的中文、英文、法条、引文、案号或水印；
- 信息仍由 README 文字完整表达，图片不作为唯一说明；
- README 为每张图片提供准确的中文替代文本；
- 图片存入仓库后再引用，不使用临时路径或外部图片链接。

## 表现方式

- 核心价值使用三列表格，避免连续九条以上的列表。
- 工作流使用短链路代码块或紧凑表格，不使用 Mermaid，以保证 GitHub 和其他 Markdown 阅读器稳定显示。
- 安装命令保留 PowerShell 与 Bash，使用清晰的小标题，不折叠首次安装所需信息。
- 仓库结构使用 `<details>` 折叠，降低页面长度。
- 硬边界使用引用提示框，第一句明确“不得编造引用、页码、案号、法条或期刊要求”。
- 标题层级从 `#` 到 `###` 连续，不跳级。

## 仓库许可文件

项目根目录已经存在标准 MIT `LICENSE` 文件。README 不新增独立的 License 章节，只在首屏显示 MIT License 徽章并直接链接 `LICENSE`。不得重复创建许可证文件，也不得修改现有许可证正文和版权人。

## 验收标准

- GitHub Markdown 中标题、徽章、表格、代码块和 `<details>` 均能正确渲染；
- 两张仓库内图片存在、可加载、风格统一且没有伪文字、Logo 或水印；
- README 所有本地相对链接均存在；
- 项目根目录保留现有 MIT `LICENSE`，首屏徽章可以正确打开该文件；
- 使用指南完整覆盖准备、模式选择、调用、工作稿和终检；
- 不删除安装命令、反编造规则、Obsidian 权限边界和 Skill 适用范围；
- 不新增未经核验的兼容性、认证、版本或录用承诺；
- `git diff --check`、Markdown 本地链接检查和 Skill 校验通过；
- 与书稿 Skill 视觉一致，但项目名称、价值主张、工作流和核心能力保持独立。

## 范围外

- 不修改 `SKILL.md`、参考文件或模板内容；
- 不创建 Logo、网站、文档站、产品截图或带文字的信息图；
- 不改仓库名称、License 正文或远程默认分支。
