## 一、设计原则

1. **保持 A 的形态**：单技能、纯 Markdown（无脚本、无依赖、无更新器）、git 工作流；新增内容融入现有文档结构，不新增顶层目录。
2. **只吸收通用规则**：B 条款逐条过筛——凡依赖"知识库 / 121 案 / 工伤研究 /《政治与法律》 / 每日检修"等具体语境的，一律不采纳或通用化重写。
3. **不复制文件、不搬运语料**：只吸收规则并重新表述；新增文件从零撰写；不携带 B 的任何项目示例。
4. **不改变 A 的既有立场**：保留"核验门禁制开放世界"（允许、且应去官方源核验）；B 的"闭世界"只吸收其**防幻觉内核**，以"环节分离"方式落位（材料获取/核验 ≠ 写作/查询）。

## 二、采纳清单（7 项，全部经通用化重写）

### F1 材料边界与查询纪律（吸收自 B"闭世界查询纪律"）

- **B 出处**：写作技能 SKILL.md §闭世界查询纪律；legal-research-wiki §Closed-World Query（v3.1.0）；legal-wiki-audit-repair §CLOSED-WORLD（v3.2.0）。
- **通用化重写为四条**（不沿用"闭世界"之名——A 不假定存在知识库）：
  1. 写作用料只来自：**用户提供的材料 + 用户授权范围内可核验的正式来源**；模型记忆永远不是来源。
  2. 材料范围未覆盖 → 如实说明"现有材料中没有"，标记 `[待核]` / `[来源不明]`，并给出补充方案（去哪里补、补什么）；不得用模型记忆"补全"、不得脑补。
  3. **占位材料不算掌握**：只有条目、摘要线索而无原文 / 页码 / 条文 / 案号的材料，按 `LEAD_ONLY` 对待；拿到原文前不得据此写具体表述。
  4. **环节分离**：联网检索属于"材料获取与核验"环节——新获取材料必须先登记来源台账（来源、定位、核验日期、状态）才能进入写作；写作 / 查询环节不得引入台账以外的事实性信息。
- **落位**：`SKILL.md` 新增章节；`references/evidence-and-legal-validity.md` 增"材料边界"小节。

### F2 五问需求拆解（通用版）→ 新增参考文件

- **B 出处**：`five-questions-framework`（B 自述为"通用需求拆解工具，不限于法学"）。
- **通用化处理**：去 wiki 化（删除"写入 concepts/、先建库后定思路"等介质措辞，改为"先收集材料、分模块给建议"）；保留：Q1—Q5 顺序、一次问 1—3 个、不猜需求、**用户已确立研究/行文思路时结构服从用户思路（不得用推演结构覆盖）**、答案整理成研究/写作设计后执行。
- **落位**：新增 `references/requirement-decomposition.md`；`SKILL.md`"建立任务边界"加一行路由。

### F3 逻辑链完整性纪律（反断言，通用化）

- **B 出处**：写作技能 SKILL.md §逻辑链完整性纪律（user confirmed 2026-08）。
- **通用化处理**：保留总纲与三类命题要求，删除 121 案 / 工伤示例：
  - 总纲：结论不得以断言出现；每个核心命题呈现完整推理链——证据 → 归纳 → 排除竞争解释 → 处理反方 → 结论。
  - 实证归纳命题：分组呈现证据（非单例举例）→ 共同特征 → 排除竞争解释 → 反方 / 边界 → 归纳。
  - 规范性命题：制度功能 → 规范任务 → 判断结构 → 法定依据（不依赖隐含前提）。
  - 统计性命题：口径交代 → 样本限定 → 不外推趋势。
  - 检查清单：连接词（"由此可见 / 因此"）前后回查；隐含前提显式化；结语可倒推问题提出。
- **落位**：`SKILL.md` 论证章节加要点；`references/argumentation-diagnostics.md` 设展开小节。

### F4 改稿继承关系透明

- **B 出处**：`legal-paper-argumentation` §三（改稿继承关系透明、在旧稿基础上发展）。
- **通用化**：
  - 改稿交付时主动附"新旧稿继承说明"（对照表：沿用 / 修改 / 新增 / 新证据来源），与 A 的反馈落实表配套；不等用户追问才交代。
  - 改稿顺序：先判断旧稿骨架是否成立（询问用户或依据其确认）——成立 → 增量增强，不另起炉灶；不成立 → 重新设计并先经用户确认。
- **落位**：`references/argumentation-diagnostics.md`"反馈如何落实"节增补；`references/workflow.md` 修改轮加一句。

### F5 论据先行原则（原"反说纪律"的中性化）

- **B 出处**：写作技能 SKILL.md §反说纪律。
- **通用化**：改为中性表述——实证 / 案例类论证按"材料 → 规律 → 结论"呈现，使读者能沿材料自行复核归纳；"先断言、后举例"（举例只作说明）不构成论证。删除"不暴露先有结论"类策略性措辞，仅保留可审核性要求。
- **落位**：`workflow.md` 起草节一行；`argumentation-diagnostics.md` 对应处一句。

### F6 实证与统计材料使用纪律（压缩版）

- **B 出处**：`legal-paper-argumentation` §二（统计口径纪律）。
- **压缩为 4 条通用原则**：
  1. 口径先行：定义、分母、归类标准先定稿再统计。
  2. 精选样本比例必须带"样本内"限定，不得外推。
  3. 样本分布不均时只描述分布，不写成趋势。
  4. "数字已算出" ≠ "该数字足以支持命题"：逐条回勾论点—证据—引注表，不静默升级。
- **落位**：`references/evidence-and-legal-validity.md`"数据"小节扩写。

### F7 稿件版本管理（轻量）+ 常见错误微补

- **B 出处**：写作技能 SKILL.md §版本管理纪律。
- **通用化**：交付新版本必须升版本号并在交付说明中注明变化；旧版本保留、不静默覆盖（X.Y.Z 格式仅作建议，不强制）。
- **常见错误补 2 条**（通用条目）：结语重复正文而不给出答案；需求未确认即动手。
- **落位**：`workflow.md` 交付节；`SKILL.md` 常见错误列表。
