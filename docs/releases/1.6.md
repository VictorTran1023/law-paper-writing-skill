# 1.6：引注实质忠实度核验与改稿防失真

版本标识采用 **1.6**，Git 标签为 **v1.6**。本版适用于不同主题的中文法学期刊论文，不扩展为教材、专著、学位论文、法律意见书或个案咨询流程，也不内置 DOCX 解析或自动排版脚本。

## 本版变化

| 方面 | 执行要求 | 不强加的内容（防误判边界） |
|---|---|---|
| 正文—原文逆向核查 | 定稿前脱离起草记忆，逐条打开原件核对带注正文句与原文语义、前提和注位；长文或大改稿建议独立只读复核 | 局部润色或单节改稿仅核查受影响引注，不强制重审全文 |
| 法条与条约实质四查 | 按所涉规范核对请求方向与编章、分款主体与“但书/除外”前提；禁常识外延适用对象，禁未见条约全文推定常见条款 | 已明示原适用方向、仅将国内规定作为立法或条约磋商参照的，属合理规范论证 |
| 域外法与译本版本 | 排查资料库外文文件的立法草案（`Draft`）或非官方译本及跨源条号偏移；禁未经核查沿用二手“共×项”全称统计 | 无中译本但已据官方正式本或双语公报核准条号的，按《法学引注手册》第84条引注，不强造译者信息 |
| 典型案例与新闻通稿 | 区分案例中“法院实际裁判结果”与发布机关“典型意义/裁判要点”；会晤或会议报道如实复述表态，不拔高为“达成共识” | 不限制对裁判理由或政策导向展开明确归属的法理评析 |
| 样本转引与注位边界 | 转引他人多组实证数据时分清各自来源与分母；禁止“句末/段末一注兜底半句无据推演”，事实通报与学理观点分注 | 多个来源共同直接证明同一判断时，仍允许按体例合并设注 |
| 检索摘要与纸媒优先 | 联网检索返回的结果摘要与合成链接按 `LEAD_ONLY` 对待，须核对目标正式页面或原件；同内容有权威纸媒版面时优先引纸媒 | 保留核验门禁下的官方源头检索能力，不改为禁止联网核查的闭世界规则 |
| 表达润色与交付同步 | 识别引号连字符/加号公式词、跨界公文黑话与同构段落模具；改稿守住合句不并款、缩句不混样本、对仗不添事实、拆句重对注位；对外修改说明同步条号数据并脱敏内部工具词 | 有正式文件或文献出处的带符号专有提法按原貌保留；单稿交付不强制另附修改对比报告 |
| Obsidian 课题隔离 | 同一 Vault 多课题共存时严守同库异题隔离；库内既有文件仍须核验是否为生效正式本 | 保持默认只读指定范围边界，不扩展为建库或修库工具 |

原有研究问题诊断、通用论证检查（1.5）、摘要规则（1.4.2）、《法学引注手册》（第二版）默认体例及目标期刊要求优先原则继续保留；`SKILL.md` 首句适用范围简介保持不变。

## 场景与实际验证

本版新增公开场景文件 [引注实质忠实度与改稿防失真场景](../../evals/citation-fidelity-cases.md)（C1—C12，含9个问题识别场景与3个合理写法防误判场景），并同步更新 [压力测试指引](../../evals/pressure-tests.md)、[引注审核模板](../../assets/templates/citation-audit.md)、[论点—证据—引注表](../../assets/templates/claim-evidence-matrix.md)及[投稿前检查模板](../../assets/templates/submission-checklist.md)。

本轮完成以下检验（验证状态如实区分，未重跑的历史场景不计为本轮实测）：

1. **静态与边界检查**：核验 `SKILL.md` 元数据与首部60字符适用范围边界、全仓库 Markdown 文件内部相对链接完整性、无私人项目语料或本地绝对路径残留。
2. **独立只读子会话盲测（C1—C12）**：在独立只读会话中仅提供更新后的技能规则文件与 C1—C12 题面（不提供观察标准），逐案检验问题识别与合理写法保护边界，全部12个合成场景均符合预期行为边界。该测试为单模型独立子会话合成场景检验，不是多模型稳定性验证，也不代替真实论文投稿前对法条、条约、案例和文献原件的人工核查。

## 安装与升级

发布与开发副本更新不会自动替换已安装到 Hermes、Codex 或其他宿主目录的技能副本。请先确认实际安装目录、本地修改及历史状态，再按需更新：

- **已使用 1.4.2 及之后干净历史的 Git 克隆**：在实际技能目录先执行 `git status --short --branch` 确认无未处理修改，再执行 `git pull --ff-only`，最后确认 `SKILL.md` 中 `metadata.version` 为 `"1.6"`。
- **1.4.2 历史重写前的旧克隆**：仍须先按 [历史迁移说明](../history-rewrite-1.4.2.md) 保留旧目录并在新目录重新克隆，不要直接合并旧分支或强制推回。
- **需要固定 1.6 而不跟随 main**：可在发布标签创建后使用 `git clone --branch v1.6 https://github.com/VictorTran1023/law-paper-writing-skill.git chinese-law-paper-writing-1.6`。
