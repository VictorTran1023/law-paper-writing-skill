# 1.5：通用论证检查与合理写法保护

版本标识采用 **1.5**，Git 标签为 **v1.5**。本版适用于不同主题的中文法学期刊论文，不扩展为教材、学位论文、法律意见或个案咨询流程。

## 本版变化

| 方面 | 执行要求 | 不强加的内容 |
|---|---|---|
| 按内容选择检查 | 根据任务、命题和材料触发专项检查 | 不要求每篇都有比较法、实证或证明责任 |
| 综述与贡献 | 研究不足由正文回应，贡献说明接续位置；回查代表性论著和原文 | 不制造空白，不把本次未附文献当成检索不足 |
| 章节任务 | 帽段简短承接，材料描述与规范主张分开；同案复用须有不同任务 | 纯实证描述不强迫理论证立，不重复堆综述 |
| 框架根据 | 说明规范、理论或作者推理及解释增量；有承接或修正时说明关系 | 不要求原创推论都有现成权威，也不要求每个框架修正旧理论 |
| 法律解释 | 区分法定要件、证明指标和作者分析工具 | 不暗中免除条件，也不一律否定有依据的功能解释 |
| 程序衔接 | 交代程序、主体、事实、负担及事实不明后果 | 取证帮助不等于实体当然成立，不设跨领域统一答案 |
| 结语 | 回应引言并提炼正文已经证明的结论 | 不强制展望、三段或固定顺序 |
| 引用落实 | 关键措辞必要时短引，重复引注核本次页码；待核标记与定义成对 | 不设直接引语比例，期刊正式要求优先 |

原有摘要规则、来源真实性、法律有效性、引注完整性及期刊适配门禁继续保留。本轮没有修改摘要业务规则或两份引注体例来源整理文件。

## 场景与实际验证

新增公开场景为 A13—A24、H21—H24，共16项；调整H5，并澄清H6中“观点例证”与“裁判差异或纠错过程研究”的适用分支。当前公开题面见 [论证场景](../../evals/argumentation-cases.md)、[审读场景](../../evals/review-feedback-cases.md)及[压力测试指引](../../evals/pressure-tests.md)。题面及观察标准是评估工具，不是已经全部实跑的证明。

本轮实际运行采用同一模型 `gpt-6.1-sol-900k` 的6个全新子会话，累计58个不同合成场景、71份实际答复。运行配置标示提供方为 `openai-codex`，未独立核验服务后端的模型身份。执行者读取候选规则和题面，不向其提供观察标准；原始输入、输出及逐项判断由维护者本地留存，未作为公开性能基准发布。

|---|---:|---:|---:|---:|
| 首轮：16个新增及41个既有相关场景 | 57 | 52 | 5 | 0 |
| 第一次定向重测 | 5 | 3 | 2 | 0 |
| 第二次定向及防误判检查 | 6 | 6 | 0 | 0 |

首轮遗漏涉及代表性论著补检、正文必要理论对话、例证引出方式、待核清单及软件痕迹、成对待核脚注。两份独立只读复核及一次追加边界审查后，修正规则适用条件与具体动作，再用新会话定向重测；原始不完整输出没有覆盖。

按不同修正快照的逐案最新记录，58个场景均取得通过结果；**这不是最终快照完整重跑58案，不是逐案独立抽样，也不是多模型稳定性验证**。同一批场景共享会话。H8、H12、H17—H20及F1—F8没有在本轮行为测试中重新执行，不据本版宣称摘要或全部引注格式场景行为复验完成。新增的纯实证描述边界检查未计入上述16个公开新增场景。

格式、相对链接、差异、版本及公开信息检查在发布前另行执行。静态检查、合成短场景表现与完整论文质量不是同一层证据；本版不保证录用，也不代替真实法律、案例和学术来源核验。

## 安装与升级

发布与开发副本更新不会自动替换已安装到Hermes、Codex或其他位置的技能副本。请先确认实际安装目录、本地修改及当前历史状态，再更新。

- **已使用1.4.2干净历史的Git克隆**：可在实际技能目录先检查 `git status --short --branch`，无未处理修改时执行 `git pull --ff-only`，再核对 `SKILL.md` 的版本。快进失败时检查分支，不使用强制覆盖。
- **1.4.2历史重写前的旧克隆**：先按 [历史迁移说明](../history-rewrite-1.4.2.md) 保留旧目录、在新目录重新克隆，不把旧历史合回主干；该说明中的v1.4.2是历史迁移锚点，不是本版最新版本。
- **需要固定1.5而不跟随main**：可在一个新的目录克隆本版标签：

```bash
git clone --branch v1.5 https://github.com/VictorTran1023/law-paper-writing-skill.git chinese-law-paper-writing-1.5
```

固定标签的副本可能处于分离HEAD状态；需要继续开发时另开分支，不在旧历史上合并。使用原来的安装方式将经过核验的副本放到实际技能目录，避免并存重名旧副本；不要自动删除自己的修改或恢复记录。新会话中明确指定技能，确认实际加载路径及版本为1.5。
